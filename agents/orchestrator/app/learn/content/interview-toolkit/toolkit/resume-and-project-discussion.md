## The resume is your question paper

Interviewers read your resume and ask about it. Every skill, project and claim is fair game. Before the interview, read each line and ask: "Can I explain this for two minutes and answer follow-up questions?" If not, remove it or study it.

## The two-minute project story

Use this order:

1. **Problem**: what did you build and why? ("A study planner for students who forget deadlines.")
2. **Your role**: what exactly did **you** do? ("I built the backend and the database.")
3. **Technology and design**: what you used and why you chose it ("Flask and SQLite because the app is small.")
4. **Challenge**: one hard problem and how you solved it.
5. **Result**: users, speed, accuracy or what you learned ("Fifty classmates used it; reminders cut missed deadlines.")
6. **Next step**: what you would improve.

:::example A sample answer
"I built a placement tracker for our college. Students were using spreadsheets and missing deadlines. I designed the database and wrote the Flask backend, and my teammate built the front end. The hardest part was sending reminders without duplicates, which I solved with a scheduled job and a sent flag. About 80 students used it during placements. If I had more time I would add email login and a better dashboard."
:::

## Questions to prepare for any project

| Question | What they want |
| --- | --- |
| Why did you choose this technology? | reasons, not "it was popular" |
| What was the hardest bug or challenge? | problem solving |
| What would you change today? | honesty and growth |
| How does it scale? | basic design thinking |
| How did you test it? | quality mindset |
| Which part did you personally write? | honesty about your role |
| How is data stored and secured? | fundamentals |
| What did you learn? | reflection |

## Resume content checklist

- One page for a fresher; clean and readable.
- **Skills** you can truly discuss, grouped (languages, tools, databases).
- **Projects** with 2 or 3 bullets each: what, how, result. Add the GitHub link.
- **Education**, marks if good, certifications that matter, internships.
- No photos, long paragraphs, or false claims. Check spelling twice.

## GitHub and portfolio

Pin your best 3 repositories. Each should have a **README** with a description, screenshots, how to run it, and the technology used. Commit regularly; a project with clear commit history is more convincing.

## If you cannot answer

Say what you know about the topic and how you would find the rest. Never claim a skill you cannot explain: one honest "I have only used it briefly" is safer than being caught.
